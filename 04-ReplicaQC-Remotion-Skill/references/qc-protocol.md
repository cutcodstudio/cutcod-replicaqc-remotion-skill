# ReplicaQC 质检协议

## 技术基线

先从参考视频和候选输出各写一份 JSON，至少包含：`width`、`height`、`fps`、视频帧数、视频时长、容器时长、音频 codec、采样率、声道数、音频时长。技术检查通过不等于视觉 1:1；它只说明时间轴和媒体流没有明显错误。

## 最低落盘文件

- `timeline.json`：`fps`、`durationInFrames`、场景列表、每个场景的起止帧和关键视觉属性；
- `qc-round-01.json`（每轮递增）：输入文件哈希、采样帧、每个维度分数、发现、修复建议、是否通过；
- `change-log.md`：每轮改了哪些源文件和参数，以及改动理由；
- `evidence/reference-f*.png` 与 `evidence/candidate-f*.png` 或等价 contact sheet；
- `evidence/ffprobe-reference.json` 与 `evidence/ffprobe-candidate.json`。

## 采样点

从时间轴中选固定检查点：第 0 帧、每个场景切换前后、每个快速运动的峰值、主要文字出现/消失点、最后一帧。短片可额外使用 10%、25%、50%、75%、90% 位置；长片按场景等分。每个点同时查看前后相邻帧，避免把单帧偶然相似当成时序正确。

## 记录维度

每个点记录：

- `layout_occlusion`：位置、尺度、遮挡和层级；
- `motion_timing`：出现、消失、速度、缓动和转场相位；
- `typography_color_detail`：文案、字体、字宽、颜色、边缘、渐变和细节；
- `audio_alignment`：音频起点、尾音和关键节拍；
- `technical_completion`：分辨率、fps、帧数、编码和音频流。

可用 0–2 评分每个视觉维度，也可按用户要求换成 0–10；不要把不同量表混成一个没有定义的总分。保留每个扣分点的帧号和一句可操作的修复建议。

## 迭代规则

先修复同时影响多个采样点的错误，例如整体时间偏移、画布比例和主标题位置，再修复局部曲线、模糊半径、颜色和字宽。每一轮只改变能解释当前差异的参数，重新渲染并保留新旧报告。若用户给出目标分数，达到目标并通过技术检查后停止；没有目标时，完成一轮全时间轴检查并报告剩余差异，不要无限调用模型。

Gemini、Claude 或其他视觉模型可以作为评审者，但评审输入应是参考检查帧/视频和候选检查帧/视频，输出要保存为可追溯 JSON。模型分数是证据之一，不代替 ffprobe 或人工核对，也不允许在没有逐帧证据时写“1:1”。
